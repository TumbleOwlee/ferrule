# verify — What runs before every approval stop

## Verify before an approval stop

By running, never by reading:
- **Gauntlet** — `ferrule run gauntlet {slug}` runs the `[[gauntlet.step]]`s of `ferrule.toml` in the run's worktree: one status line in context, full output in `{run_dir}/gauntlet.log`. The full set runs once per tree: a pass is cached by the worktree's tree, so the same tree again (committed, pushed) answers `gauntlet=pass … cached` at once. The implementer runs only its fast checks (`ferrule guide implementer`, `## Checks`); the full set is this one. `--force` reruns a cached tree.
- **A fresh `spec-reviewer` per scope** — never the planner or implementer: one sharing the author's context reproduces its blind spots. A follow-up pass in the same scope resumes that reviewer (*Principles — implementation* (`ferrule guide principles`)) with the `review.md` path and `follow-up` (`ferrule guide reviewer` `## Follow-up pass`). Plan scope: before resuming the planner with findings, the orchestrator snapshots `cp {run_dir}/plan.md {run_dir}/plan.prev.md`, so the follow-up diffs the revision itself instead of trusting the planner's account.
- **Minors never wait for the user.** The verdict names where they go: `Minors (folded into s<n+1>)` when a stage follows, `Minors (fixed before commit)` when none does — a last stage, a branch review. Folded: the orchestrator logs each as `minor=<verdict line>` on the next stage's card and repeats them in the implementer's brief. Fixed before commit: the implementer is resumed with them at once, fixes, gauntlet, no re-review, then the stage's commit (fast lane: commit on green). Only `count>0` (blockers + majors) loops, and at most **two** fix-and-review rounds per scope: findings still open after the second round go to the user as `Needs user` items on the verdict.
- **Overturned findings are logged.** The user picks another option than the verdict recommends, or calls a finding wrong (a `change`, a PR reply): log `overturned scope=<scope> count=<n> -- <the finding, ≤ 8 words>` on the parent card. `ferrule run metrics` sums them per run — the evidence for tuning `ferrule guide reviewer`'s axes, never a reason to drop a finding mid-run.
