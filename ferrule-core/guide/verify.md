# verify — What runs before every approval stop

## Verify before an approval stop

By running, never by reading:
- **Gauntlet** — `ferrule ci gauntlet {slug}` runs the `[[gauntlet.step]]`s of `ferrule.toml` in the run's worktree: one status line in context, full output in `{run_dir}/gauntlet.log`. Three levels: the stage checks (`--level push --stage s<n>`) at every stage, the review level (`--level review`) at review points, the full set (no flag) at gate 3. A pass is cached by the worktree's tree, so the same tree again answers `gauntlet=pass … cached` at once. The implementer reruns none of them. `--force` reruns a cached tree.
- **A fresh `fe-reviewer` per scope** — never the planner or implementer: one sharing the author's context reproduces its blind spots. A follow-up pass in the same scope resumes that reviewer (`ferrule guide show principles --section 'Principles — implementation'`) with the `review.md` path and `follow-up`. Plan scope: before resuming the planner with findings, the orchestrator snapshots `cp {run_dir}/plan.md {run_dir}/plan.prev.md`, so the follow-up diffs the revision itself instead of trusting the planner's account.
- **Minors never wait for the user.** The verdict lists them as `Minors (fixed before commit)`: that stage's implementer fixes every one with the blockers and majors, before the commit, no re-review of the minors alone. Only `count>0` (blockers + majors) loops, and at most **two** fix-and-review rounds per scope: findings still open after the second round go to the user as `Needs user` items on the verdict.
- **Overturned findings are logged.** The user picks another option than the verdict recommends, or calls a finding wrong (a `change`, a PR reply): log `overturned scope=<scope> count=<n> -- <the finding, ≤ 8 words>` on the parent card. `ferrule run metrics` sums them per run — the evidence for tuning the review's axes, never a reason to drop a finding mid-run.
